# CIV2 — playtest e feedback

Este repositório recebe **erros, dificuldades de entender e sugestões** de quem joga CIV2. Não contém o código do jogo.

**[Jogar](https://civ2-voronoi.vercel.app)** · **[Enviar um relato](https://github.com/necaboullosa/civ2-playtest/issues/new?template=playtest.yml)** · **[Ver relatos](https://github.com/necaboullosa/civ2-playtest/issues)**

## Como participar

1. Entre numa conta GitHub (ou crie uma). Não precisa de convite nem de acesso ao código.
2. Abra **Enviar um relato**, escreva um título curto, escolha o tipo e conte o que aconteceu.
3. Se ajudar, acrescente o que esperava, um print/vídeo e versão, turno e aparelho. Pode anexar ficheiros no campo do print.
4. Envie. O relato ganha um número e uma conversa própria; pode voltar depois para acrescentar informação.

Se já houver um relato igual, pode comentar nele com o seu exemplo. Não é preciso procurar exaustivamente antes de relatar. Erros pequenos e coisas confusas também interessam.

O botão **Relatar problema / dar feedback**, em **Opções** nas versões que o incluem, abre este formulário com versão e turno. Nada é publicado até premir o botão de envio no GitHub. Prints são anexados por si; a partida não é enviada automaticamente.

Este espaço e os anexos são públicos. Evite dados pessoais nos prints.

## O que acontece depois

- **triagem**: recebido, ainda por analisar.
- **aguarda-informacao**: precisamos de um exemplo ou esclarecimento.
- **planeado**: decisão de corrigir ou implementar tomada.
- **em-correcao**: trabalho em curso.
- **aguarda-publicacao**: correção pronta, ainda não disponível no jogo público.
- **Fechado como concluído**: resolução publicada, com a versão indicada no comentário final.

Relatos podem ser classificados como **erro**, **clareza** ou **sugestao**. Problemas que bloqueiem o jogo ou percam progresso podem receber **prioridade-alta**. Duplicados são ligados ao relato original; ideias não escolhidas recebem uma explicação. Um relato recebido não significa que a sugestão foi aprovada.
